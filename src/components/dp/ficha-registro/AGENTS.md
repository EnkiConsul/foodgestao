# Importação de fichas
- Multi-sheet registration imports are organized per batch (unit → job/sector groups → per-sheet review) via `dp_ficha_lote_organizar`, stored in `dp_ficha_importacoes.organizacao` and read by `vinculoOrganizado`; it creates/links jobs and sectors only, never employees, so the official sheet review stays the single creation path. Hand-off notifications are super-admin only and go through the Edge Function `dp-ficha-lote-notificar` (in-app notice via `dp_ficha_lote_notificar` with the caller's session, Aveto WhatsApp logged in `dp_whatsapp_envios` as `lote_ficha`, e-mail `ficha-lote-pronto`, channels saved in `organizacao.notificacao.canais`), so the client is never left with an in-app-only notice; a manual WhatsApp link is offered only when the automatic send fails.
- Batch defaults (`organizacao.padroes`) and per-sheet drafts/group actions (`organizacao.ajustes`) are saved only via `dp_ficha_lote_ajustar` (validated, never creates employees) and only prefill the review; sheet choice > batch default, read via `escolhaDaFicha`/`dadosDaFichaLote`. Shifts apply only to sheets without read hours (`turnoPadraoDoLote`, `ajustesEmGrupo`), so registered hours are never overwritten. Opening `?lote=` resolves the batch's company and switches context once.
- Step 2 lists pending decisions first (`separarGruposCargo`: sheets without a real job, then jobs without a sector, split by the initial suggestion so rows never jump while edited) and collapses identified jobs. It saves partially: sheets without a real job ("Importação eSocial") are omitted from the payload when left for the review, so prior batch decisions are never overwritten and the per-sheet review chooses the job.
- Super admins in any company they are not titular of (`companies.user_id`) see the sticky support bar `ParametrizacaoAvetoBarra` and a "Suporte" chip in the company selector (`useModoSuporte`), with a one-tap return; it never depends on concierge rows, so it cannot silently disappear. Company context stays in the browser.
- Batch sheet status uses `pendenciasFichaLote` with the same mandatory choices as `FichaRevisaoCard` (bond, payment form, time sheet, advance, plus batch defaults); unset advance enters as non-optant (same as the server), and in units with a time clock everyone registers time unless marked otherwise (`folha_ponto` in drafts/group actions) with a reason for CLT/intermittent (`dispensaPontoExigeMotivo`), because `dp_colab_ponto_clt_padrao` turns time tracking back on without `folha_ponto_dispensa_justificativa`; "Pronta" only when the review saves without a forced stop AND the person has access data (phone/WhatsApp or e-mail, `semDadosAcesso`); otherwise "Dados de acesso". Fields missing from the PDF are listed openly, never hidden.
- Unit diagnosis in step 1 comes from `pendenciasUnidade` (`src/lib/dp/unidade-completude.ts`) as a single "Cadastro incompleto" pill; nothing in it blocks the import. National fixed holidays are seeded with category `nacional` by the unit insert trigger.
- Batch defaults and group choices share one fields-only dialog (`FichaLotePadroesCard`); people are chosen only in the step-3 list (sector chip or marked sheets with a sticky "Aplicar dados" bar), never re-listed inside the dialog, so it fits a phone without scrolling. Sector names display via `rotuloSetor` (normal case), stored values untouched. Access data is filled in one bulk list (`ContatosLoteDialog` → `montarContatosLote`, single `dp_ficha_lote_ajustar` call) that merges prior draft `dados`, because the RPC replaces `dados` per sheet.
- "Finalizar implantação" creates every ready sheet in one pass via `planejarLote` (`src/lib/dp/ficha-registro/efetivacao-lote.ts`, same inputs the per-sheet review would send) and `aplicarFichaNoCadastro` (the same `dp_ficha_aplicar` path, franchise check per person); sheets with any mandatory stop, an existing CPF or another unit/CNPJ stay for individual review with the reason. Differences from the PDF need one justification + acknowledgement recorded per employee, so the accounting record rule is kept. Ignored sheets return only via `dp_ficha_reativar` (invoker, same access as ignoring).
- Per-sheet review in a batch opens in `ConferenciaFichaGaveta` (fixed header with the person's civil name and position, single scroll area reset to top whenever the sheet changes, fixed footer); `FichaRevisaoCard` portals its actions into that footer via `rodapeContainer`, never nested sticky bars. Job choice uses the inline searchable `CargoBuscaSelect` (company jobs + one-tap "Cadastrar" of the read/typed name, CBO only with the read name), never a floating popover inside the drawer, so mobile keyboard and scrolling keep working.
- Returning users see unfinished work before any upload: without an explicit choice the page opens the newest batch still reading or with sheets to review (`envioParaAbrir`, counts from `useDpFichaResumoEnvios`), collapses the PDF upload behind "Enviar outro arquivo" and lists other pending batches; "Ignorar" always confirms (`ConfirmarIgnorarFichaDialog`), then advances with an "Desfazer" toast, and ignored sheets are reconsidered via a separate "N fichas ignoradas" strip ("Ver ignoradas", keeping four filter tabs on 360px) and the "Reativar" row button; the batch end card comes from `desfechoLote`, so a batch with ignored sheets never claims everyone was registered — this prevents re-uploading a batch that only looked lost.
