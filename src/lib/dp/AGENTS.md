# Regras de src/lib/dp

- Efetivação direta da pré-admissão e ficha do candidato por vínculo, atas de reunião, salário-família, base de sindicatos, banco de horas/compensação de feriados e escala 12x36 têm regras em `src/components/dp/preadmissao/AGENTS.md`, `src/components/dp/atas/AGENTS.md`, `src/hooks/AGENTS.md`, `src/components/dp/sindicatos/AGENTS.md` e `src/lib/dp/compensacao/AGENTS.md`.

- Leave-limit floors use `private.dp_folga_fixos_dia` and `dp_folga_fixos_periodo`: resolve the latest configuration valid on each date, count active employees once in its unit, ignore variable leave, and use the legacy weekday only without a valid configuration; explicit date exceptions and scoped quotas retain precedence, preventing calendar/server drift. `dp_folga_limite_dia` retains locking, reserve accounting and audited override authorization.
- Troca de folga em afastamento: folga coberta por atestado, licença, suspensão ou férias não é negociável — o detector único `private.dp_colab_afastado_em` barra na proposta (`dp_troca_propor`) e revalida na efetivação (`private.dp_troca_efetivar`); o portal esconde essas folgas via RPC `dp_trocas_afastamentos` (sem expor o motivo) e o helper `dataEmAfastamento` (`src/lib/dp/troca-oferta.ts`).
- Afastamentos: a lista de tipos que contam como ausência vive em `TIPOS_AFASTAMENTO` (`licencas.ts`, com `FUNDAMENTO_LEGAL`) e no banco em `private.dp_tipo_afastamento` — manter as duas iguais ao criar um tipo novo.
- Público-alvo dos bloqueios: `regra_json.alvo_tipo` (todos|cargo|setor|colaborador, padrão todos); só "todos" fecha o dia (`dp_regra_bloqueia_data`), direcionadas valem por pessoa via `private.dp_regra_bloqueia_colaborador` e `regraAplicaPessoa` — quem tem restrição no mês abre a janela 1 dia antes e, sem outra data livre, marca acima do limite com aviso ao gestor (`dp_folga_marcar`); o colaborador nunca vê o motivo.
- Troca com restrição de folga: se o solicitante ou o colega cairia em data bloqueada para ele (`private.dp_troca_restricao`), a troca nunca é efetivada direto — vai para o gestor mesmo com troca direta ligada; a proposta devolve `exige_gestor` para avisar o colaborador.
- Janela de escolha de folga: `private.dp_folga_janela_lembretes` (cron diário) notifica abertura e lembra diariamente quem falta (vira push pela fila), avisa o gestor em D+1 do fechamento, e `dp_folga_autoatribuir_todas` só atribui a partir de D+2 — o gestor sempre tem um dia para decidir.
- Alvos de bloqueio listam só quem participa da escolha de folga (`colaboradorElegivelBloqueio`); no bloqueio de um dia, quem já tem folga marcada nele não aparece.

- Pending actions load independent domains with bounded concurrency and abortable deadlines; keep the confirmed snapshot during refresh and surface read failures, so incomplete results never mean all clear.

- WhatsApp dispatch normalizes phone numbers centrally and uses explicit Android package intents with official HTTPS fallback; never assume the app opened or the message was sent.

- Disciplinar: o portal só lê vias físicas assinadas (`via_assinada_path`, advertência escrita/suspensão) via `dp_portal_meus_disciplinares()`; verbais, observações e minutas ficam no dossiê interno da ficha.
- Elogio: visibilidade privado/individual/público definida só pela RPC `dp_elogio_divulgar` (notifica o colaborador e, se público, publica no Mural da unidade via `dp_avisos`); verbais e observações nunca notificam o colaborador — reconhecimento sem expor o dossiê.
- Ponto (Art. 74 CLT) é decisão da unidade: `dp_unidade_definir_ponto` liga/desliga com cascata nos colaboradores e exige justificativa da unidade acima de 20 ativos; a ficha só pede justificativa individual quando a unidade tem ponto; unidade 20+ sem ponto e sem justificativa vira pendência e alerta no início.
- Folga dominical: colaborador > cargo na unidade > unidade, via `domingosDiferenciados`; gravada só por RPC com ciência de isonomia — sem diferenciação sem registro.
- Leave requests use shared discrete-date adapters for swaps; only approved operational absences block registration. Compensatory assignment validates unit/individual eligibility on the server and persists source-linked evidence transactionally, without calendar attendance balances or inferred payroll decisions.
- Payment calendar milestones come from the pure `pagamentos-marcos` engine fed by unit rules and unit holidays; the portal receives only its own eligible rules via `dp_portal_meus_pagamentos`, so forecasts never promise pay to ineligible bonds.
- Operation panorama: justified absence counts as absence, never as a medical certificate; rest/dispensation subtypes (Art. 488, bank, compensation, swap) and leave-linked occurrences take no category, and the scale exit uses the last attendance of every visible termination process of the current contract — so effectivated notices never return people to the scale.
- Portal calendar: "Lotado" (`taken`) only when the store day has no vacancy; a used personal monthly quota is `quota` and moves the own leave directly via `dp_folga_remarcar`. Store routine lists colleagues on fixed weekly rest as off (`dp_portal_equipe_fora_dia`) and groups unshifted people into the single named shift with identical hours (`rotina-dia-agrupamento.ts`) — swaps stay reachable without inventing schedule.
- Moving one's own leave directly (`dp_folga_remarcar`) cancels, in the same transaction, the employee's pending "MUDANCA_DE_FOLGA" requests for the same source or target day; employees cancel their own pending requests only through `dp_solicitacao_cancelar` — the manager queue never keeps requests that lost effect.
- Notification audience is explicit: the manager bell reads shared admin notices plus the user's own personal ones, the portal reads only the user's own (`notificacaoNaAudiencia`, also applied in the query), because the manager read permission reaches employees' personal rows. Portal swap proposals notify the invited colleague in `dp_notif_troca`, and the store routine shows "Aguardando colega/gestor" instead of "Trocar" for open swaps (`trocasAbertasComColegas`) — the server's duplicate check stays the defense.
- Regras de ficha de registro (divergência, histórico, importação) ficam em `src/lib/dp/ficha-registro/AGENTS.md`; regras de excedente de colaboradores, franquia e teste grátis ficam em `src/lib/billing/AGENTS.md`.
- Portal leave self-service is a separate switch, `dp_config_dp.folga_marcacao_portal` (unit config over company): when false, `private.dp_folga_portal_exigir_liberada` rejects employee leave mutations and `dp_folgas_janela_efetiva` reports the window and auto-assignment as off; an inactive window alone still means free marking, so never reuse it as the lock. Colleague swaps are a separate decision: `dp_troca_propor` checks only the unit swap rule (`private.dp_troca_portal_exigir_permitida`, mode and scope), and the portal shows swaps via `trocaLiberadaNoPortal`, so turning off self-scheduling never turns off swaps.
- Unit registration steps come from `UNIDADE_ETAPAS` (`unidade-etapas.ts`), shared by the tab bar and "Salvar e avançar"; after each save the dialog compares against the just-saved unit, never the one loaded on open.
- Signing mode (phone vs paper) is an append-only dated history in `dp_colaborador_modo_assinatura`, written only by `dp_colaborador_modo_assinatura_definir` and resolved server-side at issue time (`dp_colaborador_modo_assinatura_em`, trigger `trg_dp_documento_modo_assinatura`); the browser helpers in `modo-assinatura.ts` only display it, so issued documents never change retroactively and portal receipts are refused for paper signers in `dp-recibo-emitir` (WhatsApp link stays an explicit exception).
- Scheduled holiday routines (automatic convocation, manager D-10/D-5 reminders) run without a session and must use `private.dp_feriados_resolver_base`; the public resolver keeps the member check over the same core. Convocation follows the configured closing day + 3 regardless of the portal leave window and never includes 12x36 (Art. 59-A).
